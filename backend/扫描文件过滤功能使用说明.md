# 扫描文件过滤功能使用说明

## 功能概述

本功能为项目扫描阶段添加了文件过滤能力，可以根据配置控制只处理特定类型的文件，并排除测试文件等不需要的文件。

## 配置参数

在 `application.properties` 中配置以下参数：

```properties
# 扫描文件过滤配置
# 是否启用扫描文件过滤
scan.filter.enabled=true

# 允许的文件扩展名列表（逗号分隔）
scan.filter.file-extensions=.java,.xml,.yml,.yaml,.properties

# 是否排除测试文件（*test.java, *Test.java, *TEST.java）
scan.filter.exclude-test-files=true

# 自定义排除模式列表（逗号分隔，支持通配符）
scan.filter.exclude-patterns=*test.java,*Test.java,*TEST.java
```

## 参数说明

### scan.filter.enabled
- **类型**: boolean
- **默认值**: true
- **说明**: 控制是否启用文件过滤功能。设置为 false 时将不过滤任何文件。

### scan.filter.file-extensions
- **类型**: String (逗号分隔)
- **默认值**: 空
- **说明**: 指定允许处理的文件扩展名列表。只有以这些扩展名结尾的文件才会被处理。
- **示例**: `.java,.xml,.yml,.yaml,.properties`
- **注意**: 如果此列表为空，则包含所有文件（受其他过滤条件限制）。

### scan.filter.exclude-test-files
- **类型**: boolean
- **默认值**: false
- **说明**: 是否自动排除测试文件。启用后将排除匹配以下模式的文件：
  - `*test.java`
  - `*Test.java` 
  - `*TEST.java`

### scan.filter.exclude-patterns
- **类型**: String (逗号分隔)
- **默认值**: 空
- **说明**: 自定义排除模式列表，支持 Ant 风格的通配符匹配。
- **示例**: `*temp*.java,Mock*.java,*.tmp`
- **通配符支持**:
  - `*`: 匹配任意字符序列
  - `?`: 匹配单个字符

## 过滤逻辑

文件过滤按以下顺序执行：

1. **启用检查**: 如果 `scan.filter.enabled=false`，包含所有文件
2. **文件路径获取**: 从 DiffEntry 中获取文件路径
3. **扩展名检查**: 检查文件扩展名是否在允许列表中
4. **测试文件排除**: 如果启用测试文件排除，检查是否匹配测试文件模式
5. **自定义模式排除**: 检查是否匹配自定义排除模式

只有通过所有检查的文件才会被包含在扫描结果中。

## 使用示例

### 示例1: 只处理Java和XML文件
```properties
scan.filter.enabled=true
scan.filter.file-extensions=.java,.xml
scan.filter.exclude-test-files=false
scan.filter.exclude-patterns=
```

### 示例2: 排除测试文件和临时文件
```properties
scan.filter.enabled=true
scan.filter.file-extensions=.java,.xml,.yml,.yaml,.properties
scan.filter.exclude-test-files=true
scan.filter.exclude-patterns=*temp*.java,*.tmp,*bak
```

### 示例3: 禁用过滤（包含所有文件）
```properties
scan.filter.enabled=false
```

## 日志记录

过滤功能会在日志中记录以下信息：

- 过滤统计：总文件数、过滤掉的文件数、保留的文件数
- 调试信息：每个被过滤掉的文件及其原因
- 排除模式：当前生效的所有排除模式

示例日志：
```
INFO  - 文件过滤完成: 总文件数=150, 过滤掉=45, 保留=105
DEBUG - 排除模式: [*test.java, *Test.java, *TEST.java, *temp*.java]
DEBUG - 文件扩展名不匹配，跳过: script.py
DEBUG - 匹配测试文件模式，跳过: UserServiceTest.java
```

## 性能影响

- **正面影响**: 减少不必要的文件处理，提升扫描性能
- **配置开销**: 过滤逻辑本身的开销很小
- **内存使用**: 减少加载到内存的文件数量

## 注意事项

1. **配置生效**: 修改配置后需要重启应用
2. **通配符匹配**: 使用 Ant 风格通配符，不是正则表达式
3. **大小写敏感**: 文件名匹配是大小写敏感的
4. **路径处理**: 过滤基于文件名，不包含路径信息
5. **性能考虑**: 过滤在扫描阶段进行，能显著减少后续处理开销

## 故障排除

### 常见问题

1. **文件被意外过滤**
   - 检查 `scan.filter.file-extensions` 配置
   - 检查 `scan.filter.exclude-patterns` 是否意外匹配
   - 查看日志中的过滤原因

2. **过滤不生效**
   - 确认 `scan.filter.enabled=true`
   - 检查配置文件语法是否正确
   - 重启应用确保配置生效

3. **性能问题**
   - 如果过滤后仍然处理很多文件，检查扩展名配置
   - 避免过于复杂的排除模式
   - 考虑在扫描前进行文件预过滤

## 扩展建议

如需更复杂的过滤需求，可以考虑：

1. **路径过滤**: 基于文件路径进行过滤
2. **内容过滤**: 基于文件内容进行过滤
3. **大小过滤**: 基于文件大小进行过滤
4. **时间过滤**: 基于文件修改时间进行过滤
