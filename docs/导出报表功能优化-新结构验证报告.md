# 导出报表功能优化 - 新结构验证报告

## 修改概述

根据用户需求，我们对导出报表功能进行了重大优化，实现了新的双Sheet Excel结构，并移除了不必要的提交者统计功能。

## 主要修改内容

### 1. 数据模型扩展

#### 新增 FileCommitDetail 类
- **位置**: `backend/src/main/java/com/example/migratediff/application/scan/FileCommitDetail.java`
- **功能**: 存储文件级别的详细提交信息
- **核心字段**:
  - 文件路径、仓库来源（Oracle/Gauss）
  - 提交哈希、提交者姓名、提交者邮箱、提交时间
  - 提交消息、提交类型、变更类型
  - 添加行数、删除行数、是否在时间范围内

#### 扩展 MultiRepoExportResult
- **新增字段**: `allFileCommitDetails` - 存储所有文件的详细提交历史
- **注解修复**: 将 `@Value` 改为 `@Data` 以提供getter/setter方法

### 2. 后端服务增强

#### MultiRepoExportService 优化
- **新增依赖**: `GitCommitHistoryService` - 用于获取文件详细提交历史
- **新增方法**:
  - `aggregateFileCommitDetails()` - 聚合所有文件的详细提交历史
  - `getFileCommitDetails()` - 获取单个文件的提交历史
  - `extractCommitType()` - 从提交消息提取提交类型

### 3. 导出格式重构

#### Excel导出 - 新双Sheet结构
**Sheet1: 文件汇总信息**
- 仓库、文件路径、覆盖率、状态
- 代码变更量（ΔO新增、ΔO删除、ΔG新增、ΔG删除）
- **Oracle最后提交者、Oracle最后提交时间、Oracle提交数**
- **Gauss最后提交者、Gauss最后提交时间、Gauss提交数**

**Sheet2: 文件详细提交列表**
- 文件路径、仓库来源、提交哈希
- 提交者姓名、提交者邮箱、提交时间
- 提交消息、提交类型、变更类型
- 添加行数、删除行数、是否在时间范围内

#### CSV导出 - 简化结构
- **移除**: 提交者统计部分（`appendAuthorStatsSection` 方法）
- **保留**: 文件汇总信息，包含核心提交信息字段
- **优化**: 按仓库分组显示，提高可读性

### 4. 功能特性

#### 提交类型识别
自动识别以下提交类型：
- `feature` - 功能开发
- `bugfix` - 错误修复
- `refactor` - 代码重构
- `hotfix` - 紧急修复
- `test` - 测试相关
- `docs` - 文档更新
- `style` - 代码格式
- `chore` - 构建工具
- `other` - 其他类型

#### 时间范围支持
- 支持指定时间范围的提交历史筛选
- 标记每个提交是否在时间范围内
- 默认时间范围：2025-11-01T00:00:00Z 至 2025-12-02T23:59:59Z

## 导出格式对比

### 修改前
- **Excel**: 单Sheet，包含提交者统计信息
- **CSV**: 包含文件信息 + 提交者统计

### 修改后
- **Excel**: 双Sheet结构
  - Sheet1: 文件汇总信息（重点关注）
  - Sheet2: 文件详细提交历史
- **CSV**: 仅包含文件汇总信息，移除提交者统计

## 技术实现要点

### 1. 数据流
```
MultiRepoExportRequest
    ↓
MultiRepoExportService.export()
    ↓
1. 聚合文件基本信息
2. 丰富提交信息 (CommitInfoAggregatorService)
3. 获取详细提交历史 (GitCommitHistoryService)
4. 构建MultiRepoExportResult
    ↓
ExcelMultiRepoReportWriter.write()
    ↓
Sheet1: 文件汇总信息
Sheet2: 文件详细提交列表
```

### 2. 性能考虑
- 使用缓存机制避免重复获取Git历史
- 限制单个文件的提交数量（最多50个）
- 按需获取详细提交信息

### 3. 错误处理
- Git操作失败时的降级处理
- 空值的安全处理
- 异常情况的日志记录
