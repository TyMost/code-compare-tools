# Migration 模块设计（中文整合版）

## 1️⃣ 设计原则

| 关注点                                | 领域层                                                                 | 应用层                                                                       | 关联方式                                                   |
| ---------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------ |
| 迁移文本生成                             | 提供 `generateTemplate(DiffBlock block, DecisionType decision)` 返回字符串 | 遍历 DeltaGroup → 调用领域层生成每个 DiffBlock 的迁移文本 → 组成 `blockResults`             | 应用层负责收集、聚合并生成 MigrationResult                          |
| 决策 Insert / Update / Skip / Delete | 提供 `classifyBlock(DiffBlock block)` → `DecisionType`                | 根据 `DecisionType` 决定是否写文件或回退                                              | 领域层只计算决策，应用层据此执行迁移动作                                   |
| 预览模式                               | 返回纯字符串模板                                                            | 聚合 BlockResult → MigrationResult → 前端显示                                   | `previewMigration()` 调用领域层 → 聚合结果 → 返回 MigrationResult |
| 文件写入 / 应用 / 回退                     | 无                                                                   | 遍历 DeltaGroup，根据 DecisionType 写入/删除目标文件，更新 MigrationStatus 和 OperationLog | 使用领域层生成的文本进行落地，同时记录操作元数据                               |

---

## 2️⃣ 推荐调用流程

```text
DeltaGroup
  │
  ▼
遍历 DiffBlock
  │
  ├─> 领域层 classifyBlock(DiffBlock) → DecisionType
  │
  └─> 领域层 generateTemplate(DiffBlock, DecisionType) → templateString
       │
       ▼
  应用层收集 BlockResult(templateString, DecisionType, blockMetadata)
       │
       ▼
  MigrationResult(blockResults, affectedFiles, message)
       │
       ├─ previewMigration(): 返回 MigrationResult 给前端
       └─ applyMigration(): 遍历 blockResults，根据 DecisionType 写入文件
           └─ revertMigration(): 回退 apply 的文件
```

---

## 3️⃣ 核心职责

### 领域层（GenerateAppService）

* 只负责计算和文本生成，不关心 Git 或文件路径
* 核心方法：

  * `classifyBlock(DiffBlock)` → Insert / Update / Skip / Delete
  * `generateTemplate(DiffBlock, DecisionType)` → 模板字符串
* 优点：

  * 业务规则集中、易测试
  * 可单元测试 DecisionType 判定与模板生成

### 应用层（MigrationAppService）

* 遍历 DeltaGroup，收集 BlockResult
* 根据 DecisionType 执行落地：

  * Insert / Update → 写入文件
  * Skip → 忽略
  * Delete → 手动提示或删除
* 管理 MigrationStatus 和 OperationLog
* 提供接口：

  * `previewMigration(DeltaGroup)` → 聚合模板预览
  * `applyMigration(DeltaGroup)` → 文件写入 + 状态更新
  * `revertMigration(MigrationResult)` → 回退应用文件
* 负责分支切换、并发处理、写文件/回退逻辑

---

## 4️⃣ DiffBlock 场景映射

| 场景    | 条件                      | 模板              | 说明            |
| ----- | ----------------------- | --------------- | ------------- |
| 1     | `deltaO` 存在, `deltaG` 空 | Insert          | 直接输出源代码片段     |
| 2     | 两者存在, 内容不同              | Update          | 保留原实现并输出建议片段  |
| 3     | 两者存在, 内容一致              | Skip            | 不输出           |
| 4     | `deltaO` 空, `deltaG` 存在 | Delete / 提示     | 默认为手动删除提示，可配置 |
| 5     | 两者空                     | Skip            | 仅信息提示         |
| 6/7/8 | 部分覆盖 / 内容不一致            | Insert 或 Update | 根据覆盖率和相似度阈值选择 |

---

## 5️⃣ 模板示例

**Insert**

```text
/** 迁移生成的代码片段开始
 * 请按照 project_rules.md 修改适配
 */
${deltaO.code}
/** 迁移生成的代码片段结束 */
```

**Update**

```text
/** 迁移适配段
 * 请按照 project_rules.md 修改适配
 */
/** 目标仓库原实现开始 */
${deltaG.code}
/** 目标仓库原实现结束 */
/** 迁移适配建议开始 */
${deltaO.code}
/** 迁移适配建议结束 */
/** 迁移适配段结束 */
```

* Delete 输出 `// TODO: remove target implementation manually`，可禁用
* 部分覆盖按配置阈值判断 Insert / Update
* 注释、空行、本地化由模板选项统一控制

---

## 6️⃣ MigrationResult

* 聚合所有 BlockResult
* 预览模式 → 返回模板字符串
* Apply 模式 → 写文件 + 更新状态
* Revert 模式 → 回退 apply 的文件

---

## 7️⃣ 错误处理

* Block 级错误记录在 `blockResults.errorMessage`
* 服务层日志警告
* 配置缺失/无效 → 使用默认模板
* Apply 实现后增加回滚逻辑

---

## 8️⃣ 测试计划

1. 场景覆盖：Insert / Update / Skip / Delete / 部分覆盖
2. 模板文本验证
3. MigrationResult 字段验证
4. 异常情况：空 DeltaGroup、配置缺失、仓库异常
5. 未来：Apply/Revert 备份、回滚、权限测试

* 应用层 = 遍历 DeltaGroup → 调用领域层 → 文件落地 + 状态管理 + 日志
* 通过 **DiffBlock + DecisionType + 模板字符串** 连接二者

## 6️⃣ 模板写入替换实现

* **写入入口**：MigrationAppService.applyInternal 仍在应用层收敛 BlockResult，保持原有备份、目录创建和覆盖率分析步骤。
* **UTF-8 读取**：先读取目标文件并去除 BOM，便于在 Windows 和 *nix 环境下保持一致。
* **模板替换策略**：依据生成模板的首、尾注释定位已有片段；若成功命中则原地替换，保留围绕模板的空行结构。
* **兜底逻辑**：若未检测到标记（首次写入或手动调整导致标记缺失），回退为追加写入，同时在返回信息中附带告警。
* **写回方式**：使用 `Files.write(..., StandardCharsets.UTF_8)` 覆盖写回，同时继续生成 `.bak` 文件供回滚使用。
* **反馈信息**：成功后返回的 `MigrationResult.message` 会包含告警提示，便于前端或操作日志展示。
* **测试覆盖**：新增 `MigrationAppServiceTest` 覆盖替换成功、标记缺失回退两种场景，确保模板替换逻辑在 JDK 8 下稳定运行。

```text
                        │  (多个 DiffBlock)   │
                        └─────────┬──────────┘
                                  │

          │                                         │

│   领域层 (Generate)  │                   │   应用层 (Migration) │
│----------------------│                   │----------------------│
│ classifyBlock(block) │                   │ 收集 BlockResult      │
│ → DecisionType       │                   │ templateString        │
│ generateTemplate(...)│                   │ DecisionType          │
│ → templateString     │                   │ blockMetadata         │
└─────────┬────────────┘                   └─────────┬────────────┘
          │                                         │
          │   DecisionType + templateString        │
          │----------------------------------------┘
          ▼
 ┌───────────────────────────────┐
 │        BlockResult             │
 │ ┌───────────────────────────┐ │
 │ │ templateString             │ │
 │ │ DecisionType               │ │
 │ │ blockMetadata              │ │
 │ └───────────────────────────┘ │
 └───────────────┬───────────────┘
                 │
                 ▼

       │     MigrationResult     │
       │------------------------│

                                 │
                                 ▼

```

### 流程说明：

1. **DeltaGroup**：包含多个 DiffBlock，每个块有 deltaO / deltaG。
2. **领域层**：

   * `classifyBlock` → 决策类型 (Insert / Update / Skip / Delete)
   * `generateTemplate` → 模板字符串
3. **应用层**：

   * 收集 BlockResult
   * 聚合成 MigrationResult
   * 根据 DecisionType 执行落地/回退
4. **MigrationResult**：

   * 既可用于预览，也可用于应用和回退操作
   * 聚合了每个块的模板、决策和元数据


明白，这里用 Markdown ASCII 线框图画出 **ΔO / ΔG 块匹配决策 + Insert/Update/Skip/Delete 流程**：

```text
                       ┌─────────────────────┐
                       │      DiffBlock       │
                       │  deltaO / deltaG     │
                       └─────────┬───────────┘
                                 │
                                 ▼
                        ┌────────────────┐
                        │ classifyBlock()│
                        └─────────┬──────┘
                                  │
                 ┌────────────────┴─────────────────┐
                 │                                  │
                 ▼                                  ▼
          deltaO 存在?                          deltaO 空
                 │                                  │
         ┌───────┴─────────┐               ┌────────┴─────────┐
         │                 │               │                  │
       deltaG 存在?        deltaG 空      deltaG 存在?      deltaG 空
         │                 │               │                  │
   ┌─────┴─────┐       ┌───┴───┐      ┌────┴─────┐       ┌────┴────┐
   │           │       │       │      │          │       │        │
 内容一致?    内容不一致?  Insert   Skip Delete提示?   Skip
   │           │
┌──┴──┐     ┌──┴───┐
│Skip │     │Update│
└─────┘     └──────┘
```

### 流程说明：

1. **判断 deltaO 是否存在**：

   * 如果不存在，进入 `deltaO 空` 分支。
   * 如果存在，继续判断 deltaG。

2. **判断 deltaG 是否存在**：

   * `deltaG 空` → Insert
   * `deltaG 存在` → 比较内容：

     * 内容一致 → Skip
     * 内容不一致 → Update

3. **deltaO 空 分支**：

   * deltaG 存在 → Delete / 手动提示
   * deltaG 空 → Skip
