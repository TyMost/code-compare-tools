# 时间区间差异比对改造方案

## 背景
- 目前 `/api/scan/full` 与 `/api/scan` 都依赖调用方显式传入 Oracle/Gauss 两套 `repoPath`、`branchFrom`、`branchTo`。在实际部署中我们已启用**预设模式**（见 `backend/src/main/resources/application.properties` 中 `migratediff.presets[*]`），通过配置文件集中维护默认仓库与分支组合。
- 运行环境使用 **JDK 8**，实现方案必须完全兼容该版本：建议统一使用 `java.time` 包（JDK 8 原生），避免需要更高版本的 API。
- 在临时排查或跨团队联调场景中，开发者往往只知道「某段时间内谁推送了代码」，很难快速定位到具体分支甚至没有本地分支。四分支配置模式拉起环境成本高。
- 用户希望能够仅指定一个时间区间，由系统自动找到该区间的最早与最晚提交，再计算二者的 diff；若本地缺少提交，应在差异计算前自动 `fetch`。

## 改造目标
1. 允许在 `ScanRequestDTO` → `DiffRequestDTO` 中以**时间窗口模式**、**分支模式**或二者组合的方式描述比对范围。
2. 根据用户提供的时间窗口，在后端计算出“最早/最晚提交”并复用现有 `GitRepoScanner.scan` 管线生成 diff。
3. 在计算前自动 `fetch` 缺失的提交（沿用 `RepoConfig.fetchIfMissing` 逻辑），保证本地对象数据库可解析时间区间内的提交。
4. 完整更新后端、前端与文档，记录默认 Git 行为与改造后的差异。

## 现状梳理
| 层级 | 位置 | 说明 |
| --- | --- | --- |
| DTO | `backend/src/main/java/com/example/migratediff/api/dto/DiffRequestDTO.java` | 只包含 `repoPath`、`branchFrom`、`branchTo`、`deltaType`、`includeWorkingTree` 等字段 |
| Mapper | `ScanMapper.toInput` | 读取预设、校验 oracle/gauss 字段并组装 `DiffSummary` |
| 域模型 | `RepoConfig` / `RepoBranch` | 仅支持分支名与布尔配置，不知道时间窗口 |
| Git 解析 | `GitBranchFetcher.resolveBranchPair` | 通过 `branchFrom`/`branchTo` 在 `Repository` 中解析 `ObjectId`，找不到时根据 `fetchIfMissing` 自动 `git fetch` |
| Diff 计算 | `GitRepoScanner.scan` | 组合分支提交 ID，调用 `DiffFormatter`，等价 `git diff <base> <target>` |

## 改造方案
### 0. 预设模式补充
- 预设由 `ScanPresetProperties` 绑定 `application.properties` 中的 `migratediff.presets`。每个预设包含 `source`/`target` 两套 `DiffRequestDTO` 字段。
- 当前默认预设 `default-og`（`examples/o` vs `examples/g`）写法如下：
  ```properties
  migratediff.presets[0].name=default-og
  migratediff.presets[0].source.path=D:\Coding\code-compare-tools\examples\o
  migratediff.presets[0].source.branch-from=refs/heads/o1
  migratediff.presets[0].source.branch-to=refs/heads/o2
  migratediff.presets[0].target.path=D:\Coding\code-compare-tools\examples\g
  migratediff.presets[0].target.branch-from=refs/heads/g1
  migratediff.presets[0].target.branch-to=refs/heads/g2
  ```
- **改造要求**：时间区间字段需同时支持在预设中配置（作为默认值）与在请求时覆盖。即：
  - 在 `application.properties` 中允许填写 `migratediff.presets[*].source.time-from`、`time-to`、`ref-hint` 等新字段。
  - `ScanMapper.mergeWithPreset` 逻辑：先读预设默认值，再用请求体覆盖；引入时间字段后保持相同步骤，确保调用方在“预设 + 时间覆盖”场景下体验一致。
  - 前端在“选择预设”后，可仅填写时间区间即可触发“预设路径 + 时间窗口”模式，无需重复输入分支。

### 1. 模型与 DTO 扩展
- `DiffRequestDTO`：新增 `timeFrom`、`timeTo`（建议 ISO-8601 字符串）、`refHint`（可选，默认 `branchTo` 或 `HEAD`）字段，允许只提供时间区间。实现时在字段上补充中文注释，解释含义与格式限制（示例：“时间上界，ISO-8601，示例：2025-11-05T12:00:00+08:00”）。
- `RepoBranch`：增加 `Instant timeFrom/timeTo` & `String refHint`，便于在域模型层区分解析方式。由于我们处于 JDK 8，请使用 `java.time.Instant` 并在字段上标注注释提醒调用代码注意时区转换。
- `RepoConfig`：引入枚举 `CommitLocatorMode`（`BRANCH`, `TIME_RANGE`, `HYBRID`）或等价布尔标记，串联整条链路，同样在新字段与关键方法处补充中文注释描述决策逻辑。

### 2. Mapper & 校验
- `ScanMapper.mergeWithPreset`：透传新增字段；若请求只提供时间区间，则允许覆盖预设中的分支名。
- `ScanMapper.validateDiffRequest`：新增校验逻辑，要求至少满足下列条件之一：
  1. 同时指定 `branchFrom` 与 `branchTo`
  2. 指定时间区间 `timeFrom/timeTo`（允许 open interval，但需至少一端存在）
- `DiffMapper.toDomain`：把 `timeFrom/timeTo/refHint` 写入 `RepoBranch`，并在 `RepoConfig` 中记录定位模式。

### 3. Git 提交解析
- 在 `GitBranchFetcher` 中新增：
  ```java
  public ObjectId resolveCommitByTime(Repository repo, Instant targetTime, String refHint);
  ```
  使用 `RevWalk` + `RevSort.COMMIT_TIME_DESC` 遍历 `refHint`（默认 `branchTo`、`HEAD` 或用户指定远程分支），找到：
  - `baseId`: `>= timeFrom` 的最早提交（倒序遍历时可记录最后一个满足条件的提交）
  - `targetId`: `<= timeTo` 的最新提交
- 若请求同时提供分支与时间，优先按分支解析；若分支解析失败再退回到时间模式。
- 在解析前复用现有 `fetchIfMissing` 逻辑：当 `tryResolve` 返回 null 时自动 `git fetch <remoteName>`，确保 `RevWalk` 有完整的 commit graph。
- 解析完成后，把 `commitId` 回填到 `RepoBranch`，其余 diff 管线无需改动。

### 4. 前端 & API 文案
- **前端暂不改动**：当前 UI 仅保留最基础功能并关闭多配置支持，因此此次迭代只需调整 API 文档与后端行为。等 UI 解禁配置后，再按本方案扩展时间区间表单。
- 文档示例仍需覆盖时间区间请求体（供 postman/脚本调用），前端未改动不会影响接口兼容性。建议将下列示例添加到 `docs/backend/api/Migratediff-API-Manual.md`：
  ```json
  {
    "presetName": "default-og",
    "persistResult": true,
    "oracle": {
      "repoPath": "D:/Coding/code-compare-tools/examples/o",
      "timeFrom": "2025-11-01T00:00:00+08:00",
      "timeTo": "2025-11-05T12:00:00+08:00",
      "refHint": "refs/heads/o2"
    },
    "gauss": {
      "repoPath": "D:/Coding/code-compare-tools/examples/g",
      "timeFrom": "2025-11-02T00:00:00+08:00",
      "timeTo": "2025-11-05T12:00:00+08:00",
      "refHint": "refs/heads/g2"
    }
  }
  ```

### 5. Git 行为对照
| 场景 | 现有命令等价 | 改造后命令等价 |
| --- | --- | --- |
| 按分支 | `git fetch origin && git diff branchFrom branchTo` | 同现有 |
| 时间区间 | 不支持 | `git fetch origin && git rev-list <refHint> --since=<timeFrom> --until=<timeTo>`, 取首尾 commit，再 `git diff <earliest> <latest>` |
| 含工作区 | `git diff branchFrom` + working tree | `includeWorkingTree=true` 时，仍由 `GitRepoScanner` 以 `FileTreeIterator` 作为 target |

## 风险与注意事项
- **性能**：长时间窗口会触发 `RevWalk` 遍历大量提交，需在 UI/后端限制最大跨度或分页。
- **时区与格式**：后端使用 `Instant` 存储，解析时统一使用 `OffsetDateTime.parse`，避免本地/服务器时区不一致。
- **空区间**：若区间内没有提交，需明确返回“找不到提交”的业务错误而不是空 diff。
- **安全性**：自动 fetch 时需考虑凭据和网络开销，可通过配置开关禁用。
