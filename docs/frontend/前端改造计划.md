# 前端改造计划（同步最新后端接口规范）

## 1. 背景与关键结论
- **taskId 用途**：后端在扫描时会将结果缓存到 `ScanResultStore`，后续 `detail`、`migrate.generate/apply/revert` 都通过 `taskId + filePath` 精确定位同一批扫描数据。若前端不携带 `taskId`，后端只能退回“最新一次”扫描，存在串号风险。
- **coverage 指标**：`coverage` 表示 Oracle 侧增量在 Gauss 中的覆盖率（0–1 小数）。前端需按百分比展示（乘 100 并格式化），以体现迁移成效。
- **预设配置**：扫描请求可使用 `presetName`，后端会从 `application.properties` 中的 `migratediff.presets[...]` 读取仓库路径、分支等默认值并注入缺省字段。
- **迁移 API**：`/api/migrate/generate`、`/api/migrate/apply`、`/api/migrate/revert` 均已实现，且必须传入 `taskId` 与 `filePath`。前端需完整接入三步流程。
- **非核心功能暂缓**：配置管理、操作日志、系统设置等前端模块当前仅依赖静态/预设值，需先从界面与路由中移除，避免误导用户。

## 2. 接口差异与调用约定
| 场景 | 后端真实接口 | 现状差异 | 前端调整 |
| --- | --- | --- | --- |
| 全量扫描 | `POST /api/scan/full`，请求体为 `ScanRequestDTO`（含 `presetName`/仓库配置、`persistResult`、可选 `taskId`） | 前端尚以 `GET /api/diff/scan` 为主，未提交仓库参数 | 改为 `POST`，按需求补齐仓库信息，记录返回的 `taskId`、`summary`、`diffMatrix`/`coverage` |
| 差异详情 | `POST /api/scan/detail`，需 `taskId`、`filePath` | 前端使用 `GET /api/diff/detail` 且不传 `taskId` | 按新接口提交 `taskId`，消费返回的 `oracleDiff`、`gaussDiff`、`migrationDiff`、`stats`、`coverage` |
| 迁移生成 | `POST /api/migrate/generate`，需 `taskId`、`filePath`、`options` | 仅预留按钮 | 接口接入并覆盖 `migrationDiff`，记录新的 `taskId`（后端可能回传刷新） |
| 迁移应用 | `POST /api/migrate/apply` | 未接入 | 调用后刷新详情，并提示“Migration applied” |
| 迁移回滚 | `POST /api/migrate/revert` | 未接入 | 接入并提示“Migration reverted” |
| 预设列表 | `GET /api/scan/presets` | 未使用 | 可选：用于预填仓库配置 |

> 注：分页和增量扫描暂不实现，可先保留接口占位但不在 UI 暴露。

## 3. 前端整改重点
- **API 层 (`frontend/api`)**  
  - `diff.js`：封装 `scanFull(request)`、`fetchDetail(taskId, filePath)` 等 POST 请求，并保持 `taskId` 贯通；新增对 `summary.overallCoverage`、`diffMatrix[].coverage` 的解析。  
  - `migrate.js`：实现 `generateMigration`、`applyMigration`、`revertMigration`，请求体含 `taskId` 与 `filePath`；保留 `options` 结构（如忽略空白、注释）。  
  - `request.js`：统一处理 `{ status, message, data }` 响应；`status !== 'success'` 时抛错，便于全局提示。

- **状态管理（`frontend/store/diff.js` 等）**  
  - 在 state 中记录当前 `taskId`、`summary`、`diffMatrix`、`overallCoverage`。  
  - actions：`scanFull` 保存后端返回的 `taskId`；`fetchDetail` 将 `coverage`、`stats`、`migrationDiff` 同步至 store；迁移相关 action 在成功后刷新 `fetchDetail`。  
  - mutations：新增对 `taskId` 与 `coverage` 的写入；确保所有 detail/迁移调用都读取最新 `taskId`。

- **页面与组件**  
  - `DashboardPage.vue`：触发扫描时构造请求体（若使用预设，仅传 `presetName` 与 `persistResult`），接收结果后缓存 `taskId`，并在 Diff 列表展示 `coverage` 百分比及 `status`。  
  - `DiffMatrix.vue`：新增 `coverage` 列（百分比），状态映射包含 `pending`、`oracle-only`、`gauss-only` 等枚举。  
  - `FileDiffPage.vue`：从路由或 store 获取 `taskId`，请求详情时必传；在信息面板展示 `coverage` 百分比、增删统计；支持迁移三按钮（生成/应用/回滚），按钮状态根据异步请求切换。  
  - `DiffToolbar.vue`：调用对应迁移 API；`generate` 成功后刷新详情；`apply`、`revert` 按钮在未生成 `migrationDiff` 前禁用。  
  - 逐步删除配置、日志、设置页面及其路由/菜单（详见下一节）。

- **路由与交互**  
  - Dashboard → FileDiff 跳转时，携带 `taskId`、`filePath`（建议放在 query 或 params）。  
  - 全局通知统一使用后端返回的 `message`；错误时提示 `message || '请求失败'`。

- **Mock 策略**  
  - 如需保留 Mock，更新 `mock/diffMock.js` 结构与真实响应一致（含 `taskId`、`coverage`、`stats`）；默认关闭 Mock，文档说明如何开启。

## 4. 功能裁剪与代码调整
- **配置管理（repos）**  
  - 现阶段仅依赖 `presetName`；前端暂时移除 Repo 配置页面及 `RepoConfigCard` 等组件，避免与真实仓库配置冲突。  
  - 如需展示默认仓库信息，可在扫描结果摘要中只读显示 `preset` 来源。

- **操作日志 / 系统设置**  
  - 后端接口暂未用于当前流程（需进一步确认实现）。先从路由、导航、Vuex 模块中删除相关代码，避免发送无效请求。  
  - 保留 README 说明：功能将在后端接口稳定后再恢复。

- **代码清理**  
  - 删除与上述功能相关的 store modules、api 封装、组件、路由注册及菜单项。  
  - 更新文档/注释，提示这些模块已暂时下线。

## 5. 联调与验证
1. 触发 `scanFull`（POST），确认成功获取 `taskId`、`diffMatrix`、`coverage` 并渲染至 UI。  
2. 选择某文件，调用 `scan/detail` 验证 `taskId` 携带正确。  
3. 依次执行 `migrate/generate`→`migrate/apply`→`migrate/revert`，验证状态提示与重新拉取详情逻辑。  
4. 检查 `coverage` 百分比展示是否与后端传值一致。  
5. 确认配置、日志、设置入口已移除且无多余 API 请求。

## 6. 风险与待确认事项
- **taskId 生命周期**：确认前端是否需要提供“继续使用上一次扫描结果”的入口，或每次操作都重新扫描。  
- **预设扩展**：若未来允许用户自定义仓库，需恢复配置页面并适配 `/api/repos`、`/api/settings`。  
- **覆盖率阈值**：UI 展示的百分比若需标色，请与后端沟通推荐阈值。  
- **迁移日志**：`apply`/`revert` 目前仅返回提示；若后续需要展示 logId，需扩展响应消费逻辑。
