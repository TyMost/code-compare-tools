🔧 返回总览自动跳转问题修复

问题描述

用户在文件对比页面点击"🏠 返回总览"按钮时，会自动跳转回默认的第一个仓库，而不是保持之前选择的仓库状态。

🎯 修复方案

采用状态保持 + URL参数传递的组合方案：

修复前（问题）

  • DashboardPage初始化时总是选择第一个仓库
  • FileDiffPage返回时不传递仓库信息
  • 用户选择的仓库状态丢失

修复后（解决方案）

  • FileDiffPage返回时传递当前仓库ID
  • DashboardPage监听URL参数恢复仓库状态
  • 智能仓库选择逻辑，优先保持用户选择

📝 具体修改

1. FileDiffPage.vue - 修改返回总览逻辑

// 修改前： goToDashboard() { this.$router.push({ name: 'Dashboard' }); } // 修改后： goToDashboard() { const query = {}; if (this.storeTaskId || this.taskId) { query.taskId = this.storeTaskId || this.taskId; } const currentRepoId = this.getCurrentRepoId(); if (currentRepoId) { query.repoId = currentRepoId; } this.$router.push({ name: 'Dashboard', query: query ); }

2. DashboardPage.vue - 添加URL参数监听

// 新增路由监听： watch: { '$route.query.repoId': { immediate: true, async handler(newRepoId) { if (newRepoId && newRepoId !== this.currentRepoId && this.availableRepos.length > 0) { await this.handleRepoChange(newRepoId); } } } }

3. store/diff.js - 智能仓库选择逻辑

// 修改前：总是选择第一个仓库 if (repos.length > 0) { const firstRepoId = repos[0].id; commit('setCurrentRepoId', firstRepoId); } // 修改后：智能选择优先级 let targetRepoId = null; // 1. 优先保持当前仓库选择 if (state.currentRepoId && state.repoDataCache[state.currentRepoId]) { targetRepoId = state.currentRepoId; } // 2. 选择有缓存的仓库 if (!targetRepoId && repos.length > 0) { const cachedRepo = repos.find(repo => state.repoDataCache[repo.id]); if (cachedRepo) { targetRepoId = cachedRepo.id; } } // 3. 最后才选择第一个仓库 if (!targetRepoId && repos.length > 0) { targetRepoId = repos[0].id; }

🧪 测试步骤

验证修复效果：

  1. 启动前端应用，进入总览页面
  2. 选择第二个或第三个仓库（非第一个）
  3. 点击任意文件进入文件对比页面
  4. 在文件对比页面点击"🏠 返回总览"按钮
  5. 验证：应该返回到之前选择的仓库，而不是第一个仓库
✅ 预期结果：返回总览时保持用户之前选择的仓库状态，提供连续的用户体验。

🔍 技术细节

仓库选择优先级

  1. 当前仓库状态保持 - 如果已有选择且有缓存数据
  2. URL参数恢复 - 从路由参数中获取repoId
  3. 缓存仓库优先 - 选择有缓存数据的仓库
  4. 第一个仓库兜底 - 作为最后的备选方案

状态传递流程

FileDiffPage.getCurrentRepoId() → 获取当前仓库ID → goToDashboard() 构建URL参数 → DashboardPage 监听路由变化 → handleRepoChange() 切换仓库 → 保持用户选择状态

🎉 修复效果

用户体验提升：

  • ✅ 避免不必要的数据重新加载
  • ✅ 提供连续的操作体验
  • ✅ 支持URL直接访问特定仓库
